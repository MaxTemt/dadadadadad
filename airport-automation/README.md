# Система автоматизации работы аэропорта

Курсовой проект: клиент-серверное приложение для управления рейсами, пассажирами,
бронированием билетов, аналитикой, текстовыми отчётами и резервным копированием.

## Архитектура

```
┌──────────────────────────┐        TCP + Java-сериализация        ┌──────────────────────────┐
│  Swing-клиент (Java 17)  │  Request / Response (команды)  ⇄     │ Многопоточный TCP-сервер │
│  роли: ADMIN / USER      │                                       │  пул потоков + пул БД    │
└──────────────────────────┘                                       └────────────┬─────────────┘
                                                                                │ JDBC
                                                                       ┌────────▼─────────┐
                                                                       │   MySQL 8 (InnoDB)│
                                                                       └──────────────────┘
```

* Вся бизнес-логика, проверка прав и работа с БД выполняются на сервере.
* Клиент не имеет прямого доступа к базе данных.
* Каждое клиентское подключение обслуживается отдельным потоком из пула.
* Протокол — Java-сериализация объектов `Request` / `Response` поверх TCP.
* Пароли хранятся в виде PBKDF2WithHmacSHA256 (120 000 итераций, соль).

## Модули Maven

| Модуль   | Назначение |
|----------|------------|
| `common` | Модели предметной области, enum-ы, DTO, протокол, исключения, утилиты, валидация |
| `server` | Конфигурация, пул соединений, DAO, сервисы, команды, аналитика, отчёты, backup/restore, TCP-сервер |
| `client` | Swing-интерфейс, сетевое подключение, диалоги, таблицы, диаграммы |

## Требования

* JDK 17+
* Maven 3.8+
* MySQL 8.0+

В проекте уже настроены Maven Wrapper-независимые команды; при необходимости укажите
`JAVA_HOME` на установленный JDK 17.

## Подготовка базы данных

```bash
mysql -u root -p < db/schema.sql
```

Скрипт создаёт базу `airport`, пять связанных таблиц в 3НФ и демонстрационные данные.
Для отдельного пользователя БД раскомментируйте последние строки `db/schema.sql`:

```sql
CREATE USER IF NOT EXISTS 'airport'@'localhost' IDENTIFIED BY 'airport';
GRANT ALL PRIVILEGES ON airport.* TO 'airport'@'localhost';
FLUSH PRIVILEGES;
```

Параметры по умолчанию: `jdbc:mysql://localhost:3306/airport`, пользователь `airport`,
пароль `airport`. Они задаются в `server/src/main/resources/server.properties`,
в `server.properties` рядом с jar или аргументами командной строки.

## Сборка

```bash
mvn clean package
```

Результат:

* `server/target/airport-server.jar`
* `client/target/airport-client.jar`

## Запуск

### Сервер

```bash
java -jar server/target/airport-server.jar
```

С параметрами:

```bash
java -jar server/target/airport-server.jar \
  --host 0.0.0.0 --port 5555 \
  --db-url "jdbc:mysql://localhost:3306/airport?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC&characterEncoding=UTF-8" \
  --db-user airport --db-password airport \
  --threads 16 --pool-size 10 \
  --reports-dir reports --backups-dir backups
```

Справка: `java -jar server/target/airport-server.jar --help`.

Конфигурацию можно хранить в файле `server.properties` рядом с jar и передавать
через `--config path/to/server.properties`. Приоритет: аргументы командной строки →
файл `--config` → `server.properties` в рабочем каталоге → ресурсы classpath.

### Клиент

```bash
java -jar client/target/airport-client.jar
```

Параметры подключения:

```bash
java -jar client/target/airport-client.jar --host 192.168.1.10 --port 5555
```

Также поддерживается `client.properties` в рабочем каталоге.

## Возможности

### Пользователь

* просмотр рейсов с поиском и фильтром по статусу;
* просмотр и редактирование пассажиров;
* оформление, изменение и отмена бронирований, регистрация на рейс;
* просмотр аналитики и диаграмм;
* формирование текстовых отчётов по рейсам и бронированиям, сохранение отчёта
  в локальный файл (на сервере отчёт также остаётся в каталоге `reports`);
* просмотр списка отчётов, сохранённых на сервере, и их повторное открытие
  через меню «Отчёты → Отчёты на сервере».

### Администратор

Всё перечисленное выше, плюс:

* добавление, изменение и удаление рейсов;
* управление справочником авиакомпаний;
* удаление пассажиров и бронирований;
* управление учётными записями (создание, роли, блокировка, сброс пароля);
* создание и восстановление резервных копий (XML-файлы в каталоге `backups`);
* защита от удаления последнего активного администратора и собственной учётной записи.

## Структура базы данных

| Таблица      | Назначение |
|--------------|------------|
| `users`      | сотрудники и учётные записи |
| `airlines`   | справочник авиакомпаний |
| `passengers` | пассажиры и документы |
| `flights`    | рейсы, расписание, статусы, цены |
| `bookings`   | бронирования, связь рейса и пассажира, класс, стоимость, статус |

Связи: `flights.airline_id → airlines.id`, `bookings.flight_id → flights.id`,
`bookings.passenger_id → passengers.id`, `bookings.created_by → users.id`.

## Реализованные технологии и приёмы

* собственная иерархия классов: `AbstractEntity → Person → User / Passenger`,
  а также `Flight`, `Booking`, `Airline`;
* наследование классов JDK: `JFrame`, `JPanel`, `JDialog`, `AbstractTableModel`,
  `SwingWorker`, исключения;
* интерфейсы и абстрактные классы: `CommandHandler`, `Refreshable`, DAO-интерфейсы,
  `AbstractJdbcDao`, `ChartPanel`;
* паттерны проектирования:
  * **Command** — `CommandHandler` + `CommandRegistry`;
  * **DAO + Factory** — `DaoFactory`, `Jdbc*Dao`;
  * **Template Method** — `AbstractJdbcDao`, `ChartPanel`;
  * **Builder** — `ServerConfig.Builder`;
* инкапсуляция, перегрузка и переопределение методов, статические методы и константы;
* сериализация объектов модели и протокола (`Serializable`, `serialVersionUID`);
* обработка исключений: проверяемые `AirportException` и наследники, централизованная
  обработка ошибок в `CommandRegistry` и `UiUtils`;
* многопоточность: пул потоков сервера, пул соединений с БД, `SwingWorker` в клиенте;
* параметризованные SQL-запросы (`PreparedStatement`) и транзакции при восстановлении копии.

## Тестирование

```bash
mvn test
```

Интеграционный тест `AirportServerIntegrationTest` поднимает реальный TCP-сервер на
свободном порту и использует H2 в режиме MySQL. Проверяются:

* авторизация и разграничение прав;
* CRUD рейсов, пассажиров и бронирований;
* сохранение статуса существующей брони при его отсутствии в запросе;
* аналитические показатели и диаграммы;
* формирование, сохранение и чтение текстовых отчётов;
* создание и восстановление резервной копии;
* параллельная работа восьми клиентов.

H2 используется только в тестах (`test` scope); рабочее приложение работает с MySQL
через официальный JDBC-драйвер `mysql-connector-j`.

## Каталоги данных

* `reports/` — текстовые отчёты, созданные на сервере;
* `backups/` — XML-файлы резервных копий.

Каталоги создаются автоматически при первом обращении. Пути настраиваются параметрами
`--reports-dir` и `--backups-dir`.
